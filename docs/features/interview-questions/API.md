# Interview questions — read API

## Routes

| Route | Visibility |
| --- | --- |
| GET /api/v1/interview-questions | Active Member/Admin; published, not flagged for review |
| GET /api/v1/interview-questions/{id} | Same visibility; hidden/missing UUID returns 404 |
| GET /api/v1/admin/interview-questions | Active Admin; includes drafts |
| GET /api/v1/admin/interview-questions/{id} | Active Admin; includes draft answers and variants |

Unversioned `/api/interview-questions` and `/api/admin/interview-questions` aliases match existing feature routes. All routes require authentication. Anonymous requests return 401; Member requests to admin endpoints return 403.

List query: `page` (default 1, max 1,000,000), `pageSize` (default 20, max 100), `search` (max 200 characters, case-insensitive literal substring), `level` (basic/intermediate/advanced), `department`, `topic` (each max 100 characters). Department and topic use exact array containment in JSONB. Invalid query values return 400. Pagination orders by UUID for deterministic results; it is not a snapshot across concurrent changes.

List response: `{ items: [{ id, question, slug, level, status, needsReview }], total, page, pageSize }`. Detail response: `{ id, status, data }`; `data` is the original JSON object, not an escaped JSON string. Render answer/code content as text, not executable HTML.

## Persistence and deployment

`InterviewQuestion` maps to `gdsc.InterviewQuestions`; `Data` is JSONB and the searchable scalar columns are generated by PostgreSQL. EF treats them as computed columns. `AddInterviewQuestions` creates the table on a fresh database or adopts the existing table from `seed-postgres.mjs` without deleting/reimporting records. Downgrade deliberately retains the table and its data because it may predate EF ownership; physical removal is a separate manual operation. Up can adopt the retained table again.

Startup applies migrations under the existing application initialization flow. Seed data separately using `node luyenphongvan/seed-postgres.mjs`; the dataset is not bundled into the API container. An empty database therefore has an empty question list until seeded.

`access` is source metadata, not an application billing entitlement. Draft filtering currently hides incomplete Pro records. No edit/publish/delete API is included in this read integration.

## Verification

Local startup also exposed legacy seeder cleanup that deleted memberships before attempting to delete an account referenced by roadmaps. Automatic account cleanup has been removed from startup; regression coverage ensures existing seed accounts survive initialization. Account removal must be an explicit administrative operation.

`InterviewQuestionTests` requires `ROADMAP_TEST_POSTGRES`, creates its own disposable database, and covers fresh migration, adoption with existing rows, generated columns, JSONB filters, pagination, preserved answers, admin/member visibility, HTTP 200/400/401/403/404 and model snapshot consistency.
